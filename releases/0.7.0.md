# IQwurksPunch 0.7.0

**Release type:** Payroll review, approval, locking, exception management, reporting metadata, authorization, and CSRF security release  
**Release version:** 0.7.0  
**Release date:** July 27, 2026

---

## Overview

Version 0.7 introduces a structured, auditable payroll-review and approval workflow for IQwurksPunch.

Payroll administrators can now create defined payroll periods, review payroll exceptions, record immutable notes, approve completed payroll, lock finalized payroll, and reopen approved or locked periods when corrections are required.

Approved and locked payroll periods protect their underlying punch records from later correction. Protection is applied using the configured company timezone so stored UTC punch timestamps are compared against the correct company-local payroll date.

Payroll-period workflow information is also integrated into web reports, CSV exports, PDF documents, employee time cards, manual email reports, and scheduled email reports.

Version 0.7 additionally strengthens application security with database-backed user authorization and centralized CSRF protection for all POST requests.

This document describes the final Version 0.7.0 release. The release commit and Git tag are created after the final validation step.

## Highlights

### Payroll Periods

Version 0.7 adds formal payroll-period records.

Administrators and supervisors can:

- Create a payroll period
- Assign a descriptive period name
- Select inclusive start and end dates
- Review periods newest first
- Open a period-detail page
- View the current workflow status
- Open the corresponding Payroll Workspace report
- Review creation, review, approval, and lock metadata

Payroll-period dates use the configured company timezone.

A payroll period may contain no more than:

```text
31 calendar days
```

Overlapping payroll periods are rejected.

Payroll-period states are:

```text
open
under_review
approved
locked
```

### Payroll Review Workflow

The payroll workflow provides explicit state transitions.

Supported forward transitions are:

```text
open -> under_review
under_review -> approved
approved -> locked
```

Supported reverse transitions are:

```text
under_review -> open
approved -> under_review
locked -> under_review
```

The workflow supports:

- Beginning formal review
- Returning an under-review period to open
- Approving reviewed payroll
- Locking approved payroll
- Reopening approved payroll
- Reopening locked payroll
- Recording the acting user
- Recording transition timestamps
- Recording required workflow reasons
- Rejecting stale or conflicting transitions
- Preserving immutable workflow history

Workflow updates use database transactions.

Status changes include expected-state checks so a stale request cannot silently overwrite a newer workflow state.

### Payroll Approval

Payroll may be approved only when its period is:

```text
under_review
```

Approval requires an explicit confirmation.

Approval is blocked while unresolved payroll exceptions remain.

Approval records:

- The approving user
- The approval timestamp
- The approved workflow state
- An immutable history entry

Approval information appears in:

- Payroll-period details
- Payroll Workspace reports
- CSV exports
- PDF exports
- Employee time-card PDFs
- Manual email reports
- Scheduled email reports

### Payroll Locking

A payroll period may be locked only after it has been approved.

Locking requires the exact typed confirmation:

```text
LOCK
```

Locking records:

- The locking user
- The lock timestamp
- The locked workflow state
- An immutable history entry

A locked period represents finalized payroll and protects the associated punch dates from correction.

### Payroll Reopening

Approved and locked payroll periods may be reopened when further review or correction is necessary.

Reopening requires:

- An authorized administrator or supervisor
- A reason containing at least 10 characters
- A reason containing no more than 1,000 characters
- A valid current workflow state

Reopening returns the period to:

```text
under_review
```

The active approval and lock metadata is cleared:

```text
approved_by_user_id
approved_at
locked_by_user_id
locked_at
```

Prior approval and lock events remain preserved in immutable workflow history.

This maintains an accurate audit trail while allowing authorized payroll corrections.

### Immutable Payroll History

Version 0.7 adds append-only payroll workflow history.

History records may include:

- Payroll-period creation
- Review beginning
- Return to open
- Approval
- Locking
- Reopening
- Review-note creation
- Exception resolution
- Exception acceptance

Each history entry can preserve:

- Payroll-period identifier
- Action type
- Previous status
- New status
- Acting user
- Reason or note
- Creation timestamp

Prior events are not removed when a period is reopened.

### Supervisor Review Notes

Authorized administrators and supervisors may add immutable notes while a payroll period is open or under review.

Review-note requirements include:

- A nonblank note
- A maximum length of 1,000 characters
- An active authorized user
- A valid payroll-period state

Review-note creation records:

- The note text
- The author
- The timestamp
- A corresponding immutable history event

Existing review notes are not edited or deleted through the payroll workflow.

### Payroll Exception Review

Payroll exceptions can be synchronized from Payroll Workspace results for an exact payroll-period range.

Version 0.7 supports:

- Refreshing detected exceptions
- Stable exception identifiers
- Open exception counts
- Total exception counts
- Resolving an exception
- Accepting a reviewed exception
- Recording optional resolution notes
- Requiring an explanation when accepting an exception
- Reopening resolved exceptions when the issue returns
- Preserving accepted exceptions during later refreshes

Detected exception categories include:

```text
missing_clock_out
missing_clock_in
unmatched_meal
unmatched_break
overlapping_punch_activity
zero_duration_shift
invalid_punch_sequence
payroll_calculation_warning
```

Exception states are:

```text
open
resolved
accepted
```

An accepted exception records that the issue was reviewed and intentionally allowed.

Accepted-exception explanations require at least 10 characters and may contain no more than 1,000 characters.

Unresolved open exceptions block payroll approval.

### Protected Payroll Records

Version 0.7 prevents punch correction inside approved and locked payroll periods.

Protection applies to:

- Manual punch creation
- Punch editing
- Punch deletion
- The original date of an edited punch
- The proposed date of an edited punch

Protection is enforced in the service layer rather than only in the browser interface.

Punch timestamps continue to be stored in UTC.

Before checking payroll-period protection, the application converts a punch timestamp to the configured company timezone and compares the resulting company-local calendar date with the payroll-period range.

This prevents timezone boundaries from placing a punch in the wrong payroll day.

### Payroll Workspace Integration

Payroll Workspace reports now display payroll-period workflow information.

The report metadata service identifies whether a report range has:

```text
exact association
partial overlap
no association
```

Exact association means the report range exactly matches one payroll period.

Partial overlap means the report range intersects one or more payroll periods but does not exactly match a single period.

No association means the report range does not intersect an existing payroll period.

Available metadata includes:

- Association type
- Association message
- Payroll-period identifier
- Payroll-period name
- Payroll-period dates
- Workflow status
- Creation user and timestamp
- Review user and timestamp
- Approval user and timestamp
- Lock user and timestamp
- Open exception count
- Total exception count
- Approval-blocked state
- Protected-period state
- Payroll-period detail link

Partial-overlap and no-association results are labeled explicitly so a report is not incorrectly presented as approved or locked payroll.

### Database-Backed Authorization

Version 0.7 strengthens workflow authorization.

Administrative workflow actions no longer depend solely on role information stored in the session.

The authorization guard now:

- Reads the authenticated user identifier
- Loads the current user from the database
- Confirms that the account still exists
- Confirms that the account is active
- Confirms that the user has an authorized role
- Synchronizes current user information with the session
- Rejects access when database authorization fails

Payroll workflow actions require an active:

```text
administrator
```

or:

```text
supervisor
```

Punch-correction actions also use database-backed authorization.

This prevents a disabled, deleted, or role-changed account from continuing to rely on stale session authorization.

### CSRF Protection

Version 0.7 adds centralized cross-site request forgery protection.

The CSRF system provides:

- Cryptographically secure random tokens
- Session-bound tokens
- Constant-time token comparison
- Automatic hidden CSRF fields in rendered POST forms
- Central validation before POST routing
- Safe rejection of invalid or missing tokens
- Safe redirect behavior after rejection

All application POST requests are protected.

Logout is now performed using POST rather than GET.

The legacy state-changing route:

```text
GET /reports/send-daily-email
```

has been removed.

State-changing application behavior is no longer intentionally exposed through GET routes.

## Known Limitations

Version 0.7 does not yet include:

- Advanced payroll-period filtering
- A separate standalone workflow-history page
- A separate standalone payroll-reopen page
- Department-level payroll-review summaries
- Employee-level review-completion tracking
- Workflow-status suffixes in export filenames
- External payroll-provider export profiles
- Configurable third-party payroll field mappings
- Manual weekly payroll email delivery
- Scheduled weekly payroll email delivery
- Scheduled exception-report delivery
- PDF email attachments
- CSV email attachments
- A guided installation wizard
- An automated application-upgrade command
- Release packaging
- A universal per-command `--help` option
- Multiple companies
- Multiple physical locations
- Multiple independently managed kiosks

Payroll-period report association currently requires an exact date-range match for full workflow metadata.

A report range that intersects a payroll period without exactly matching it is labeled as a partial overlap and is not represented as approved or locked payroll.

The default production deployment continues to use HTTP on a trusted local network. Installations exposed to untrusted networks should add HTTPS before allowing remote access.
